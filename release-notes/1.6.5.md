# 1.6.5

Desktop startup fixes following the 1.6.4 release:

- Recognize the old inbox Kim judgment fields before startup recovery. Preserve the original row JSON in a same-database archive, keep all other item/brief business fields, and retain strict current IPC validation. Migration is atomic and repeatable.
- Inventory large task histories one complete snapshot at a time through the original custody checks. Retain the directory manifest and verify it again before completing the unchanged effect-inventory transaction. Do not raise graph limits, omit historical events, certify old execution closure or weaken execution/deletion checks.

1.6.4 incident diagnosis found 143 inbox items (five affected legacy judgments), 2,021 task checkpoints, 345 browser-stored threads and 14 projects on kai-mbp. The original records were retained. Empty project lists also involved old background services surviving the GUI upgrade; matching old service instances were stopped normally after identity and signed-reference source checks, allowing the new service to load the existing projects. The inventory source regression uses the actual 2,021-record scale and preserves unknown-effect deletion restrictions.

These source fixes require signed-package and actual rendered-history validation before publication. Do not treat a visible native window, source tests, or these incident counts as proof that every historical execution can be resumed or deleted. Old records without reliable physical completion receipts remain restricted; this patch does not declare them finished. macOS support remains 13.5 or later. The existing one-click old-app update limitation (#255) is unchanged. Keychain backend and per-item authorization behavior are unchanged.

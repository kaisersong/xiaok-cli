# Windows legacy 收编：持有并复核 OS 对象

#244 以现有Windows安全模块扩展一个普通OS元数据lease，不授予DSH/业务执行权限。holdProfilePaths接受有界绝对路径数组，只用当前进程TokenUser；每个现有root/目录/SQLite/sidecar/profile JSON以OPEN_REPARSE_POINT打开、拒reparse与文件多硬链、**禁止FILE_SHARE_DELETE**，owner必须精确当前SID，不采用收紧DACL时的elevated Administrators-owner例外。DACL不得允许其它普通账户；SYSTEM/Administrators按前文明确OS受信边界允许。不改owner/DACL，不修补后再当收编证明。

lease在native内保留handle、volume/fileIndex、完整owner+DACL SDDL。assertCurrent从相同handle和当前路径复核身份+完整SDDL；路径替换、ACL变化、已关闭、未知结果均拒绝。close逐一确认，不把失败当成功；Finalizer仅兜底释放，不作迁移成功证明。JS不传SID或校验回调，不接收handle数值，也不能用DTO伪造lease。直接引用真实lease对象仅授予普通OS检查/关闭，不授予source/native业务身份。

JS在identity census前持有root、multi-agent及已存在的固定三类legacy库/sidecars和profile/alias；持有覆盖census、创建UUID与alias、返回身份前复核。读操作也保持此证明；迁移相关写入采用private-at-birth文件API，census快照新目录在复制前收紧为单SID可继承ACL。不更改共享root/无关文件。已有UUID新装root没有经验证alias时不得把本root sha视为legacy；14条旧fixture逐类改成真正legacy或UUID域。拒绝外owner、Everyone/未知Allow ACE、hardlink/junction、替换与ACL中途变更，并保持原数据不变。

Windows新profile/alias写SID版本，原用户名不作为SID证明。macOS原UID/alias格式不变。已有正式旧Windows数据无可靠SID证明时继续拒绝收编，不从管理员默认owner推断是当前用户。升级后安全数据可用性和delete_pending需独立真机验证，不能把native lease通过等价完整迁移交付。

## 对抗审修订

- 新建目录也必须private-at-birth：Windows不使用mkdtemp后修补，随机名字交原生CreateDirectoryW+私有SD独占创建；新census目录/UUID/alias从第一个字节就私有。旧root或旧文件绝不修改ACL后再收编。
- 初始化模式增加固定的零字节`.continuity-profile-init.lock`，当前SID私有SD创建、OPEN_ALWAYS+share=0，校验普通单链接/当前owner/可信DACL/零长度；死亡由OS释放handle，不凭PID或mtime回收。每个实际root的初始化串行。旧库及完整WAL/SHM/journal现有文件在初始化lease中**不共享WRITE或DELETE**：活旧writer存在即拒绝；census原有双读hash/WAL checksum/元数据稳定检查保留。不存在的库/目录在返回前核对仍不存在，新增异常不放行。
- 原生接口不收任意路径表，收本机fixed drive上的root和read/initialize模式；内部固定root、multi-agent、四个库及sidecars、profile/alias白名单，逐级拒reparse，核对GetFinalPathNameByHandle规范路径与volume/fileId。只读identity模式只持有root及profile/alias，不阻断服务已经打开的数据库；初始化模式才持有库与互斥handle。SACL不参与授权，完整OWNER+DACL SDDL含控制/继承位逐次核对。
- 别名先作为不可变迁移意图独占写入并flush，包含version=2、当前SID、目标UUID和已经盘点通过的legacy域；再以同一个UUID独占创建profile(version2 SID)。崩溃时有alias无profile可在同SID/同域完整再资格后完成同UUID；有UUID无alias不认legacy sha，不猜测或重建。已有UUID与alias必须精确匹配，同一root当前文件SID/ACL同一组持有句柄保证绑定；完整alias复制/移动也必须重新证明当前root与各文件SID，跨SID拒绝。
- 发布前分别验证legacy库未改、foreign/Everyone/reparse/硬链拒绝、并发初始化、活writer拒绝、配置中途ACL变化、alias意图崩溃恢复、迁移后列表/发送/delete_pending。native通过不能代替最终产品验收。

原子发布补充（关闭半写profile恢复缺口）：UUID/profile及alias都不直接写最终名字。先在同一个已资格root下以随机temp名、当前SID私有SD、CREATE_NEW写完整JSON并FlushFileBuffers；从同一个经过owner/DACL/单链接验证的handle用SetFileInformationByHandle(FileRenameInfo,ReplaceIfExists=false)原子发布到固定目标名，再flush/确认close。最终名要么不存在、要么是完整已flush的JSON，不会出现半写profile；已存在最终文件绝不替换。alias先完整原子发布，再按alias UUID原子发布profile。崩溃留下孤立temp不被识别为身份，也不回收未知文件。root init share0锁覆盖两次发布；已有metadata read handles禁止WRITE/DELETE，解析/版本/SID/UUID不匹配一律拒绝，不尝试“修复”已有坏记录。

已存在完整UUID身份的普通启动不进行新收编，也不持有数据库写排斥：增加observe模式，metadata依旧不共享WRITE/DELETE，库文件允许WRITE共享并持有SID/完整SDDL/fileId证明；原census的双hash、时间/尺寸、WAL checksum稳定证明保留。此路仅在profile预先存在、之后仍存在且可读SID身份相同使用，不创建任何profile/alias；UUID根有legacy sha且无alias仍拒绝。无profile的新建/legacy初迁/未完成intent恢复仍走init share0+库排斥写入。这样正常重开已存在身份的桌面不会被自己的活动owner空闲写句柄拒绝；可写期间不创建新映射，旧alias及profile在readonly metadata句柄下不可写或替换。

Windows elevated 新文件的实际owner默认是Administrators。产品的普通groups/codex/continuity库新建前改用当前SID私有空文件/目录，再交SQLite，绝不chown已有legacy文件。已存在完整profile的observe模式仅对**对应主库已精确当前SID**的WAL/SHM/journal允许当前elevated TokenOwner恰为Administrators的OS-owner例外，且profile文件本身仍精确当前SID、全部Allow仍只本人或既定SYSTEM/Administrators；init迁移模式及无profile的legacy窄例外不接受此例外。profile/alias/主库/目录的owner判据不放宽，跨SID、过滤token、其它group及孤立sidecar都拒绝。此为旧映射读取兼容，不创建新UUID/alias。

允许root上方的用户环境路径别名（同macOS /var语义），但先拒dataRoot本身的reparse并固定realpath，再用canonical Native root及固定子路径；所有后续读取都使用这同一个physical root，不回头读可变logical alias。legacy旧摘要仍按Main最初logical dataRoot计算，移动/复制只能凭SID验证的既有alias映射，不猜新根sha。

## Canonical artifact 拒绝回退

Main 的 POSIX 兼容回退也必须识别 dangling symlink。`existsSync` 跟随链接会把它误当缺失；使用 `lstatSync`，仅 ENOENT 算缺失，其它错误算存在并拒绝回退。真实生产入口回归已先红（unavailable 误为 legacy），安全审查同时覆盖该兄弟路径。

## 验证记录

Codex 实现；独立 Kimi（Moonshot AI，k3.1-pro-highspeed）对 Native custody、Windows profile、Native loader 和 Main identity 的静态审查结论：无可复现 P0/P1。ilucas 固定 Node24 的迁移回归 8/8、Electron39 同一 DLL 原生回归 11/11；Mac 升级/新会话/受限删除 4/4，dangling artifact 先红后绿。类型检查、治理测试48/48、governance:check 均通过。日志位于隔离 artifacts/evidence，完整 Main Windows 验收另记，不用迁移层测试代替。

最终补验：ilucas 固定 Node24 的真实 Main 服务新装/升级连续三启、新会话发送、旧记录受限删除共4/4通过。夹具曾在关闭原 writer 后用只读 SQLite 读取自身，创建管理员 owner 的 WAL/SHM；改为原 writer 存活时取验收快照，再正常关闭，不修改旧数据 ACL、不放宽初次迁移条件。

增量审查切至 OpenCode 的 GLM-5.3-Flash（Kimi达到5小时额度）：只读审查 owner qualification、snapshot 私有出生、三个 store 的 Native 前置检查与 dangling artifact fallback，结论无可复现 P0/P1。

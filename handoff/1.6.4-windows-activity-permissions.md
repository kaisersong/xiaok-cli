# 1.6.4 Windows activity permission verification

Status: Windows Store 19/19, emitted failure/durability/crash 49/49, and Node/Electron native 20/20 passed. Final full-SHA CI and published artifacts remain pending. The release plan explicitly permits quality to determine a reasonable runner budget; Windows alone now uses a reviewed 12-second observer window for the ordinary 10,000-progress case. macOS remains at 5 seconds; no product or Native deadline changes.

The ordinary conversation activity Store owns an opaque N-API permission context. Creation allocates private buffers and the wrapper, normalizes input path spelling and captures OS exports, but opens no file/token handles. The Store installs ownership before the first verify can open OS handles. Handles pin the parent, main database, owner database, WAL, SHM and the owner transaction journal without FILE_SHARE_DELETE. Every transaction still reads the current process SID, binary owner/DACL, file identity, type and hardlink count. Permission verdicts are never cached. This is ordinary filesystem metadata, not Native/DSH authority or admission evidence.

The parent uses the existing Store predicate: eligible actual owner; nonempty allow principals restricted to current SID, SYSTEM and Administrators; a current-user FILE_ALL_ACCESS ACE with object/container inheritance and without INHERIT_ONLY. An inherited DACL is permitted. Parent permissions are observed without repair. Files retain the exact protected, current-user-only file predicate; a permitted tightening is checked again against the actual descriptor. Canonical path API results are length checked before comparison. A context failure stays failed after an ACL is repaired.

A known absent optional WAL/SHM during initial capture permits fallback only after all captured metadata handles actually close. Unknown open/check/close errors never select that fallback. Fresh WAL/SHM are created privately only when both were absent, after the exclusive owner transaction is acquired; an existing recovery pair is left to SQLite. Read-only and POSIX paths retain their existing behavior.

Each observation reads its descriptor with NtQuerySecurityObject into owned byte storage, validates successful status, bounded self-relative length, actual owner/DACL and the same binary predicates. Storage reuse never reuses a previous verdict. Nonexact file ACLs delegate to the unchanged full repair path. Transient-name existence uses actual NtQueryAttributesFile relative to the pinned directory; only STATUS_OBJECT_NAME_NOT_FOUND is absent, all other failures reject. The final parent check still observes the actual canonical path and ACL.

Metadata closes before SQLite. The separate owner database is released only after metadata and data closure both return successfully. Any unknown retains actual resource owners, rejects later writes, preserves the original thrown value, and never retries or fabricates a successful close. Finalization retains unknown contexts rather than acknowledging them.

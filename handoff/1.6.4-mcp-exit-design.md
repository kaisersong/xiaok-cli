# #221 MCP close 的进程存活

现状：src/platform/mcp/transport.ts waitForProcessExit 的普通退出和强杀后确认两段轮询都对唯一 timer unref。调用者正在 await 关闭流程，Promise 自身不保活，stdio child 已 unref 时父 Node 可先退出。

方案：仅移除两处 timer.unref；仍逐次 setTimeout，原10秒正常退出期限和1秒强杀确认期限不变，不增加后台常驻timer。修复作用于共享的生产waitForProcessExit入口及它的所有调用者，KTeam无需另复制逻辑。

对抗审（Codex）：计时器只在进行中的await内创建，完成或异常后不存在下一次timer；无无限保活。kill ESRCH仍视已退出，其它强杀错误仍抛；无需更改取消或MCP协议。必须用独立Node父进程+真实unref子进程证明自然退出，而不是Vitest中的活动句柄遮盖。

先写测试：父进程导入真实emitted transport，出生真实Node子进程并unref（stdio ignore），分别自然延迟退出和超时SIGKILL，wait返回后打印closed。旧实现父进程过早退出缺closed；新实现均打印closed且退出0。测试driver按回报pid清理自己的遗留子进程；禁止按进程名杀。先跑旧代码红，再实现两行修复，然后emitted套件与原transport用例复验。

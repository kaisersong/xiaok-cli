# #243 本版关闭 Electron Node/inspect fuse

用户已明确“本版必须完成 fuse 迁移”，原延期建议撤回。此前盘点中的“受保护 children 保留 Main executable”是现状，不是已证明不可迁移的资格条件。现已读取原 bootstrap：父 Main 的 window/source/capsule 保持原真实对象，child birth 绑定真实 process.channel/send 与固定 owner-entry；不以选中的 runtime DTO 作为任何 Native grant。

## 可行性证据

固定包内 Node24.19.0/SQLite3.53.3 已通过原 runtime manifest/executable/license hash 验证。用这个真实 binary 运行 canonical daemon/business/IPC/SQLite 三个既有套件45/45通过。它不替代真实Main安装包验收，但排除了“所有owner子进程必须Electron39 Node22”的先验假设。Main继续Electron39，不改其原资格、ABI或保护闭包。

## 实现

1. 增加共用、固定来源的 child runtime resolver。真实 packaged Electron Main 从现有锁定 broker-runtime 模块验证并选择 Node24；不采信 XIAOK_NODE_CMD/NODE_OPTIONS/NODE_PATH/ELECTRON_RUN_AS_NODE 或用户指定资源路径。缺失/损坏/不支持则失败关闭，无宿主Node或Electron Node回退。普通CLI及development保留现有行为，开发Electron才可用RunAsNode。
2. 普通Node无法读asar。afterPack将最终app.asar中的Main运行时与依赖提取到固定node-child/app物理闭包（不用于Electron Main启动），源映射保持相对布局；Main代码仍从app.asar加载。固定helper把自身asar内entry路径映射到该闭包，asar外真实服务路径不改。Node24执行的是固定JS entry；原parent-owned真实child/IPC/capsule/current/NoEscape检查保持不变，不新增调用者传入的Child或“已验证”DTO。
3. 迁移全部生产消费者：profile census、owner launcher、writer/dispatch launch、KSwarm、CLI worker及包装器、office parser、Codex的Node入口、external discussion supervisor和其它process.execPath的Node子进程。native executable（Codex exe等）不误换成Node。所有Entry/worker/dependency需实际物理可读；不得仅做字符串扫描宣称迁移完成。
4. afterPack先装固定Node/runtime closure，再用该Node做原运行时/服务/工具验收，保留所有原门禁。最终关闭RunAsNode、EnableNodeOptionsEnvironmentVariable、EnableNodeCliInspectArguments；评估并打开OnlyLoadAppFromAsar。EmbeddedAsarIntegrityValidation需结合现有afterPack重写asar和Win PE完整性表评估，未验证不能虚称开启。
5. 对最终实际app读取fuses，三个必须false；真实Main启动、profile census、owner/IPC/服务、CLI/office worker通过。负对照以恶意--eval/--inspect/NODE_OPTIONS/ELECTRON_RUN_AS_NODE尝试执行临时canary，不能执行。正常退出不用inspector。Mac/Win实际运行验收，缺平台不按源码推断。

## 安全边界

选择运行时只决定要执行的固定程序，绝不是Source/Native授权。私有Main来源、window/session实例、launch nonce、原始child descriptor、target generation、actor scope与终态/未知资源库存保持原函数。映射物理副本不能把Main入口解包成可被Electron任意载入的目录应用，OnlyLoadAppFromAsar防止该回退。保持原签名和文件校验，不放宽ABI或“资格失败则普通写入”。

## 回归先红

- packaged resolver不能返回Main executable/环境指定node，损坏runtime拒绝；development/CLI控制组。
- 最终asar内JS entry能由固定Node实际运行，所有依赖可解析，映射逃逸拒绝。
- 现有真实canonical daemon/writer/dispatch、普通service/CLI、office worker回归保持；最终fuse三项读取为关闭，退回包对照可执行canary而新包不执行。
- afterPack hooks不能继续用ElectronNode，CI验证实际产物而非配置常量。任何消费者失败先修消费者，不重新打开fuse。

## 设计评审修正

- Darwin x64补齐同版本官方Node24锁与缓存，不因本轮迁移取消Intel源码打包支持；官方SHASUMS256核对归档，再核Mach-O最低系统、executable/license字节。正式验收矩阵仍明确本轮实际运行的平台。
- 所有packaged内部Node spawn的env强制用现有sanitizeRuntimeEnv：移除NODE_OPTIONS/NODE_PATH/ELECTRON_RUN_AS_NODE/XIAOK_NODE_CMD及LD_/DYLD_，迁移后不得再追加RunAsNode。普通外部用户命令不借此扩展Native资格。
- fuse翻转位于全部afterPack内容处理之后、Developer ID/Windows分发签名之前；正式验收同时检查签名与真实fuse。arm64本地运行如需恢复Mach-O ad-hoc哈希，仅做无身份的结构修复，不访问Developer证书或公证；正式签名仍仅发布流水线执行。
- 普通Node不识asar：单独物理node-child闭包由最终asar提取，Main入口保留asar内；OnlyLoadAppFromAsar禁止把副本作为Electron目录App载入。afterPack原门禁全部改走锁定Node物理闭包；不为通过门禁重新开fuse。

## 固定 Native launcher 补充

继续追踪实际 C launcher 发现 `native/main-installation/protocol.h` 的 `MI_KSWARM_EXEC` 默认指向 Main executable；这条 Native-only 固定路径也必须迁移。生产默认改成同一已安装 bundle 内固定 Node runtime 路径；Native 仍自行 hash 固定 executable、检查 mode/link、核实际子进程 proc_pidpath，不允许 JS 参数指定 executable/argv/environment。固定 original-authority-bootstrap.js 已在 services 物理目录，保留 fd3/198、原一用 birth 和父子关联；不需要公共 node-child preloader。fixture 宏覆盖仍仅 fixture build，生产不得接受覆盖。此入口不以新 resolver DTO 作为授权。

GLM 补充评审指出同权限 Broker C launcher 也使用 Main，已纳入同一固定 Node 默认宏迁移；两条 launcher 均删除 RunAsNode env。固定路径必须位于 MI_MAIN_BUNDLE 内，依靠原整 bundle release digest、root ownership 与原进程身份检查覆盖，不声称生产逐文件固定 SHA 比较。增加生产默认宏预处理回归，并在 afterPack 对实际固定路径进行 executable/license/manifest 验证。安装仍由原 root 安装器收紧本应用闭包的属主及 mode，不改共享父目录；打包只设置本次新副本 mode，不擅自安装或获取 root。

## Native 只读 leaf 补充

全量检查 `_NSGetExecutablePath` 又发现 `readonly-leaf.h` 从当前 Main image 起 Node leaf。生产改用同一 Native 固定 `MI_PACKAGED_NODE_EXEC`，driver 保留 dladdr 定位的原物理 unpacked Native asset 与原完整 SHA/size 验证、sandbox/no-fork/memory/GO/READY/terminal/custody协议。仅编译期 NR/MI fixture 保留测试宿主 Node，生产不能 JS 选 runtime；独立 Source 无真实 Main session 仍 default deny。Node在已安装bundle树原release digest覆盖内，不扩大只读leaf资格。

leaf 评审修正：生产 header 显式包含唯一的 main-installation/protocol.h 读取固定宏，NR_FIXTURE_BUILD 或 MI_FIXTURE_BUILD 仅编译期测试构建才保留 _NSGetExecutablePath；两种情况都删除 RunAsNode env，固定宏复制带 PATH_MAX 截断检查。验收新增真实固定 Node24 的 leaf READY→bind→GO→closed 序列，最终安装包同样执行，未跑不声称完成。

关闭来源库存补充：共用 resolver 记录已进入的固定 policy；Main 原 durable-store 阶段检查其文件 FD 库存，未知 close 不可标为闭合。原 taskShutdown 已包含 multiAgent 的 quiesce 与 finalizeMultiAgentStores，因此删除 unavailable 分支重复的 lifetime.disposeMultiAgent 登记，保持唯一原 shutdown owner 和 phase-six durable barrier。旧 shutdown 用例先实际创建连续性会话再使用返回的真实 ID，不再拿不存在的固定字符串当会话。

原配置仍声明 Linux AppImage/deb，因此补齐 Linux x64/arm64 的同版本官方 Node 锁，不让 fuse 关闭后源码打包产物失去 Node host。与 Darwin x64 同样先核官方 SHASUMS 和归档成员，再实际运行目标 Node/SQLite。正式发布矩阵不凭此扩大，目标 GUI 未实跑则明确未验；未知 runtime target 在打包阶段失败而非产出必坏安装包。

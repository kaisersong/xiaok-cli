# #235 Windows 本机健康连接诊断

issue 允许“不依赖 TCP”或“检测失败并给出处理提示”。本版选择后者，不把未坐实的安全软件/防火墙推断写成根因，不自动修改系统规则，也不改 Source/Native 的健康资格条件。

SourceSupervisor 仅记录当前受控子进程启动后真实 fetch 是否在收到 HTTP response 前失败；成功获得 response 即清除此标记，JSON/manifest/PID 不匹配继续使用原错误。启动 deadline 后仍无合格 health，若实际 Windows 且最后尝试是连接失败，错误为 activity_source_start_timeout:local_connection_unavailable。birth 查询耗尽预算时不借用 spawn 前探测结果。原 reaper 必须先关闭自己创建的确切 child、删除自身 receipt，然后才返回失败；不依赖 PID/mtime 回收其它进程。

Main 的一次性通知把这个固定诊断码映射为中英文用户提示：本机后台服务无法连接，退出重开，持续失败请联系管理员检查系统网络及安全软件拦截日志。不声称版本冲突、不要求关闭安全防护、不显示内部代码、路径、token 或 header。共享文案同步 renderer locales 类型与中英文，由 app.getLocale 选择 Main 文案，普通配置不匹配文案保留。

先写回归：现有真实 child 的 health 超时/释放端口测试增加“HTTP transport 拒绝”分支，实际 Windows 才期待新码；已收到 HTTP 200 但 JSON 无效的控制分支仍保持旧码。真实 Windows Node24 上注入 fetch 失败，验证 exact child 被关闭、receipt 清空、端口可重新监听。Main 通知走真实 startup 入口，失败不阻止 KSwarm 降级启动、每类只提示一次、中英文无内部代码。独立模型审查后再改 production。

不宣称 TCP 故障已修复：本版提供明确可诊断降级和操作指导，原 #235 的真实网络策略根因与管道迁移留在 issue 继续追踪。

启动链补充：owner-runtime.ts:150-154 会在启动失败后关闭 host，Main writer launcher 最后收到的可能是 socket 断开，而非原 source 错误。因此 owner-entry 保留固定连接诊断码到当前日志，Main 对一般启动/断连失败也显示中立的管理员诊断指引，仅明确 config/profile mismatch 保留版本提示。不新增读取日志的权限、不把日志或 IPC 诊断当任何运行资格。

## 验证

Codex 实现、GLM-5.3-Flash Free 设计及最终代码审查无P0/P1。ilucas 固定Node24的真实受控 child：response-stall / HTTP200无效JSON / transport-failure 三例通过，各验证 exact PID关闭、receipt清空和原端口重新监听；transport诊断先红后绿。Main实际startup入口通知10/10，原Mac supervisor全套15/15；governance:check、Electron typecheck、完整build:main通过。具体超时类别只表示健康连接失败，不证明系统拦截来源。

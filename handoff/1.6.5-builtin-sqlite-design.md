# 1.6.5 built-in SQLite migration

User requires removal of better-sqlite3 from 1.6.5. This includes shared Desktop/CLI code and source sidecar runtime. Product stores use Electron39.8.10/Node22.22.1 node:sqlite; ordinary protected sidecars remain the fixed Node24.19 executable. Production RunAsNode, NodeOptions and NodeInspect fuses remain closed. Existing protected authority C addons remain; they enforce file/authority access and are not the removed third-party SQLite driver.

CLI engines range is explicitly raised from>=22.14.0 to ^22.22.1 || >=24.0.0 (22.x LTS or24+), matching the actual Electron runtime API baseline. CI minima and README are updated. Node22.14 has no native columns/setReturnArrays, so pretending to preserve native raw semantics there is prohibited. No Object.values row reconstruction in the native census. SQLite is an experimental Node API in this release; qualification is against pinned runtimes, and future runtime upgrades require these checks again.

## Data/storage contract
- Internal builtin-sqlite.ts subclasses the actual DatabaseSync. No Proxy, replacement addon, alternate engine or fake cppdb identity.
- Own non-configurable native open/inTransaction aliases use actual isOpen/isTransaction getters. No tracked boolean substitutes. Public prepare facade supplies current store conveniences; each Statement wraps the actual StatementSync.
- PRAGMA uses captured native prepare, bypassing public prepare replacement as the original driver did. Preserve synchronous nested savepoints and deferred/immediate/exclusive behavior; reject known async functions before invoking them, and reject thenables/rollback failures without certification. Every native result/exception retains actual values; Blob rows exposed through store facades become Buffers, original native census uses actual raw arrays.
- Actual old13.0.3 baseline was executed: foreign_keys=1; unknown named keys are ignored; undefined named values bind NULL; double-quoted string literals are rejected. Evidence /tmp/xiaok-165-builtin-old-driver-contract.json. New runtime uses FK on, DQS off, bare named keys and unknown named keys allowed, undefined->NULL. The initial review's claim that old driver rejected unknown keys was disproven by actual execution; do not change that established binding contract.
- fileMustExist uses a properly escaped SQLite file URI with mode=rw/ro. Missing files are rejected by native SQLite without a precheck/create race; test special characters and Windows URI paths.
- node:sqlite generic ERR_SQLITE_ERROR errors do not have a distinct native driver class. FULL remains unconfirmed/closed; arbitrary Error objects never certify settled capacity exhaustion. No new fake SqliteError class or code-only provenance brand.

## Original-source/authority boundaries
- Private verification opens actual native DB, captures original DatabaseSync.prepare and StatementSync methods plus own native getters and complete native/public descriptor/prototype fingerprints. Census uses only these captured methods on the exact privately opened actual receiver. Wrapper callbacks are not declared native SDK methods. Strict intrinsic/schema/function/module checks remain.
- Native SQLite schema identifiers must be actual TEXT; reject Blob/malformed identifiers before caller coercion rather than invoking Uint8Array/Buffer toString. Additive refusal, no authorization gain.
- source-sync db-exec/db-close still returns the exact original receiver. db-transaction requires raw===true after actual BEGIN EXCLUSIVE (the expression raw!==true is the refusal condition); db-open-state requires raw===false after native close. Preserve the original consumer, actual locked DB and physical resource tracking. Review alleged ternary contradiction against executable tests, not prose interpretation.
- Captured pager bytes remain immutable originals. Electron22 cannot deserialize: an exclusive0600 file in a new0700 private directory provides the parsing representation only, with readonly native SQLite open as appropriate. Header byte18/19 changes are limited to the copy as before; original capture hash is unchanged. Preserve full limits, query_only/trusted_schema and integrity checks. Native close is captured directly and actual native isOpen=false is required before unlink. Unknown close or inode/cleanup failures retain the original failure and source owner; no deletion/resume permission follows from temporary data. Test no leak on normal close and no public-close spoof.

It throws RangeError when a default Number read would exceed the safe integer range, instead of the removed driver silently rounding int64; explicit per-statement safeIntegers()/setReadBigInts preserves every bit. This stricter default is retained, not emulated with lossy conversion. Connection-wide defaultSafeIntegers does not exist: no synthetic connection-wide mode is introduced.

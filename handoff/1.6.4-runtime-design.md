# 1.6.4 运行时升级设计（2026-11-15）

基线：c453f03691cd5d10e07c486d3338b2fd810e30ae。完整需求原件：本机 projects/1.6.4-plan.md。

## 约束与现状

- 计划推荐的 Electron 44 不符合 macOS 12 下限：官方 44 breaking changes 明确要求 macOS 13。不得直接采用。
- 候选改为仍获维护的 Electron 43 最新补丁 43.8.10，必须实测包内 Node 24、Mach-O 最低系统和真实 Main 启动。
- desktop/electron/broker-runtime-package.cjs 的 Darwin <22.6 回退返回 null；普通 resolver 随后使用 Electron。固定 broker Node 24.19.0 保留，不把 Electron 当成固定 runtime 健康身份。
- after-pack.cjs 仍用 Electron RunAsNode 验证生产依赖。全项目存在多条 RunAsNode 生产子进程入口。关闭 fuse 前必须先迁移全部入口到包内独立 Node，否则不能完成 #243。此次 Electron 升级不单独关闭 RunAsNode。

## 改动

1. desktop Electron 依赖精确固定 43.8.10，安装脚本 allowScripts 同步；只更新该依赖锁，不顺带升级其它包。
2. 加运行时资格验证脚本：在真实 Electron 中运行，核 Electron 精确版本与 Node major >=24；macOS 核 app/Framework 的实际 Mach-O minos <=12.0，不把当前宿主启动等价于旧系统验证。
3. 针对脚本用独立 fake executable 覆盖错误版本、旧 Node、启动异常和不可执行；真实二进制验证另存日志。
4. 复核 39→43 breaking changes 与现有 API 调用，执行 desktop build/typecheck 与 runtime focused tests。

### 首轮审查发现的具体安装差异

Electron 42 起取消 postinstall 下载；43.8.10 的实际 index.js/cli 可能触发首次懒下载。依赖升级同时补 `prepare:electron` 显式安装入口，让 CI 在实际模块加载/验证前明确完成下载；不能只依赖 allowScripts 或改 lock。安装只使用该固定 npm 包自带的 install.js（不使用 npx 下载其它版本）。

真实 Main 测试使用现有 tests/native/helpers/electron-executable.mjs 的私有无 Dock 副本；清除 ELECTRON_RUN_AS_NODE/NODE_OPTIONS/NODE_PATH，以 process.type=browser 证明入口，20 秒子进程 timeout，Node 退出码和结果文件均检查。单独在旧 Electron 上跑反向对照。binary minos 仅是构建属性，不等价旧系统真机通过。

原生模块不盲目 rebuild：better-sqlite3 13 的 N-API 预构建先实载核验；nodejieba/keyring/sherpa 分别在最终包内用真实 Electron 路径加载，ABI 不符才按目标架构重建。afterPack 完整门禁与 Windows x64/macOS arm64 的打包验证缺一不可。macOS 通知已在 42 切为 UNNotification，未签名包通知失败不能通过启动降级通知误判为已修 NSAlert，正式签名包另测通知与拒绝权限路径。

### 审查收敛：实施与合并的分界

本设计允许开始精确依赖升级和安装路径调整，目的是取得可验证的候选运行时；不声称升级成功。PR 保持 draft，以下未齐不得 ready/合入：

1. 干净候选运行时真实 Main 入口日志；二进制完整安装，清除 ambient override，超时明确失败。旧39.8.10反向对照必须失败。
2. unsigned electron-builder --dir 执行实际 afterPack 全链，启动 unpacked Main；最终包内所有使用的原生模块逐项加载。失败先定位重建，不降低门禁。
3. macOS 主入口、Framework、所有 Helper 的每个 Mach-O slice 均解析 LC_BUILD_VERSION 或 LC_VERSION_MIN_MACOSX，缺失/未知拒绝，要求 minos <=12.0.0；原生 .node 从实际包内额外核部署下限。包内固定 broker Node 因旧系统不会执行，不算入启动集合。
4. 新增真实 Electron `node:sqlite` 能力日志（SQLite版本、DatabaseSync/StatementSync 原型），并以相同候选启动真实 Broker 拿 health。SDK 资格以 broker 的实际成功判断，不能仅凭 Node major 或把固定 runtime 版本强套回退运行时。
5. macOS12实机启动、NSAlert来源与5分钟稳定、Windows正式升级和 signed 通知仍是整版正式发布门禁；找不到环境要登记缺口，不能用 minos 属性或 macOS27实测替代。

首轮对抗审的 P1（native ABI/afterPack、回退能力、Mach-O覆盖）按上述条目收紧。原设计中的 fake executable 包装脚本方案取消，使用真实旧/新 Electron Main 退回对照；Mach-O parser 加合成多slice/缺失/高版本拒绝测试。

## 验收及未覆盖边界

- 升级 PR 仅证明依赖和本机运行时验证。macOS 12 真机、降级 broker、NSAlert 根因与 5 分钟 health、Windows 安装包、最终 fuse 及自动更新各有独立门禁，未执行不得标为通过。
- 不移除 minimumSystemVersion，不发布或移动 tag，直到完整计划必需项和真机门禁通过。
- 设计对抗审重点：Mach-O 多架构/Framework 系统下限遗漏、Electron 二进制调用挂起、环境污染、测试自证、native ABI 和 fuse 对启动链的破坏。

# Linux 无 ps 的进程身份

#223：Linux 使用内核 /proc/<pid>/stat 的第22字段 starttime 和本次 boot_id 组成 linux-proc-v1:<boot>:<ticks>。解析以最后一个右括号分隔 comm，拒错PID、截断和非数字。可读的同PID/启动tick是身份；ENOENT仍要kill(pid,0)证实ESRCH才视为dead，权限/解析错误为unknown。不凭PID、随机self标记或mtime猜测所有者死亡。macOS保留既有ps；Windows保持既有格式，本轮不制造格式冲突。

迁移：旧claim中的ps身份不能与/proc直接比较。不一致格式且PID仍存活时claim锁必须fail closed，不能把格式不同当PID复用而删活锁；确认进程已不存在后仍按原流程清理。provider source pin遇不同身份原本只返回in_use，不会放行删除，保持此保守路径。

验证：Linux真实OS读本PID/已退出子进程、无ps子进程启动新transcript、相同PID同tick/不同tick和mixed旧claim不回收；其它平台原process身份/claim锁回归。独立模型审格式迁移和死进程判据后提交。
补充设计：新linux-proc字符串不能直接写入旧claim，旧1.6.3会把格式不同当PID复用而删新活锁。Linux新claim把startIdentity持久化为封闭对象{version:3,kernelStart:string}，新parser严格解码，旧parser看到非string会fail closed，因此双向安全；老ps claim存活时新parser格式冲突也fail closed，证实PID死亡后仍可按原流程回收。其它平台和测试模拟普通identity继续旧string。崩溃留下v3 claim时旧版本会拒绝，需新版本核实死亡后清理，明确记录升级边界。若acquire在读取其它不明claim时失败，必须仅移除自己刚创建的choosing/settled记录，不能留下新的假busy。

最终代码：退出中Z/X状态为unknown，不凭状态猜dead；只有/proc缺失且kill0=ESRCH返回dead。18项通过（macOS跳过真实Linux单元项）；dgx Linux/Node24.21.0在PATH空且spawnSync ps明确失败时，真实transcript获取/活锁拒绝/释放再获取、真实子进程alive/退出dead均通过。冻结1.6.3 parser的降级对照两项先红后绿。Kimi最终代码审查无P0/P1；治理48/48。

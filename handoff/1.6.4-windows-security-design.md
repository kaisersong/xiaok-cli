# Windows SID/ACL 与进程出生时间

目标：#237 的活动文件 protected owner-only DACL、#240 的无PowerShell进程birth查询、#244的只读SID/ACL收编依据。三者共用普通Windows N-API8模块，直接调用Win32 API；不是DSH authority或资格放行。

现状：storage-permissions.ts两条Windows入口均直接return；source-supervisor.ts用PowerShell查StartTime；profile.ts全拒Windows legacy域，用户名不能证明SID所有权。不得只修某个写入口而让兄弟入口仍写公开文件。

## native API

- inspect(path)：用CreateFileW以OPEN_REPARSE_POINT/BACKUP_SEMANTICS打开句柄，GetFileInformationByHandle拒reparse、普通文件多硬链；GetSecurityInfo从同一handle读取owner和DACL。返回currentSid/ownerSid、volume/fileIndex物理身份、允许的SID列表、protected标志；null DACL/未知Allow ACE拒绝。只读，不修复legacy目录。
- protectFile(path)：仅普通文件、单链接、当前SID为owner才能执行；不接收调用者SID，不递归、不改变owner。用同一handle SetSecurityInfo写一条当前SID FullControl ACE，并设PROTECTED_DACL_SECURITY_INFORMATION；读回确认protected和唯一Allow SID。目录仅在专用活动子树/新建空快照中开放；唯一当前SID Allow带OBJECT_INHERIT|CONTAINER_INHERIT，SQLite sidecar创建即继承私有DACL。共享配置root绝不收紧，只在SQLite开库前检查当前owner和全部Allow SID限本人/SYSTEM/Administrators；这是同一明确OS受信边界，出现其它普通账户即拒绝，不等数据写入后修补。
- processBirth(pid)：整数有效PID，OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)+GetProcessTimes，转换为与原.NET UTC Ticks相同的十进制字符串，保持已存receipt兼容；结束/不可读拒绝，不以PID或时间戳猜测。

实现补充：文件在创建时就必须有DACL，不能先写密钥再收紧。增加writePrivateFile(path,content,exclusive)：SECURITY_ATTRIBUTES同时指定当前SID owner和protected单Allow DACL；CREATE_NEW模式已有文件返回false而不覆盖，普通模式仅允许已是private的现有单链接文件，在同一无共享handle校验后才截断/写入/flush。配置、凭据、endpoints、状态、ledger统一使用它；新数据库和日志先创建private空文件再交回原writer。Native凭据排除规则不变。

提升权限宿主的边界：Windows elevated token会默认创建Administrators-owned文件。protectFile仅在当前token确为elevated、TokenOwner恰是固定Administrators SID且文件owner与其相同时，允许收紧DACL；保留owner不变，不将此情况视为当前用户所有权，也不用于legacy收编。普通/过滤token不能使用该例外。所有owner、SID来自OpenProcessToken(TokenUser/TokenOwner/TokenElevation)，没有调用者SID参数。

## JS 与装配

固定模块路径，app.asar映射到unpacked；不接受环境指定addon。缺模块fail closed。N-API8构建在Windows x64，用Node与Electron两种真实宿主验加载；CLI/Desktop构建复制同一产物并记录source/binary hash。macOS保持原路径，不加载Windows模块。

活动文件：chmodPrivateActivityFile的Windows分支调protectFile；secureActivityStorage的Windows分支只遍历固定活动文件/专用子树，拒链接，排除native source credential（原规则保留）；不触碰共享root或无关文件。每次真正收紧前由native再次查当前owner，不用过期ACL缓存授权。

legacy收编：先只读检查root、multi-agent目录、groups.sqlite及已存在的continuity/profile/sidecar文件；owner必须当前SID。DACL不得允许非当前SID的普通账户；SYSTEM和Administrators是Windows固有受信管理主体，允许它们不会扩大普通账户权限，必须在审查中明确接受此口径，否则不执行收编。检查前后物理身份及安全摘要一致，再使用现有域盘点/UUID初始化/SQL迁移机制；新alias保留SID审计，不把用户名或POSIX uid=-1当证明。新UUID根不认本root sha，只有已验证legacy映射可认。失败保留原文件并降级，不覆盖历史。

审查澄清：legacy固定SID例外是明确的威胁模型——信任本机SYSTEM和已经提升的管理员，不防御掌握SeBackup/SeRestore/SeTakeOwnership的OS管理员；此类主体即使不出现在DACL中也可接管文件。没有信任普通管理员的过滤token（Administrators在该token中为deny-only，Allow ACE不授权）。该检查称“无其它普通账户访问”，不称owner-only；protected新文件仍只保留本人一条Allow。legacy必须持有无DELETE sharing的root/目录/数据句柄，至首次写入和迁移完成前复核同一物理对象及完整SDDL；未实现此持有机制前绝不接通legacy收编。

## 对抗审与测试次序

先新增测试再生产实现。Windows真实文件：protected唯一本人、Everyone Allow拒绝、外部owner拒绝、symlink/hardlink拒绝、无关共享文件不改；真实子进程birth与PowerShell只在测试中对照，同PID稳定/退出拒绝。Node22与Electron39均实际加载同一N-API产物。集成覆盖同SID收编、foreign/Everyone拒绝、UUID新装拒旧sha、delete_pending恢复与列表/发送。不能用mock SID替代真机证明。

风险：ABI稳定不等于原生依赖实际可加载；独立模型须审API句柄生命周期、ACE边界和调用者可绕过的兄弟路径，最终HEAD双端CI和两台Windows隔离根复验前不发布。

Win32依据：Microsoft GetSecurityInfo/SetSecurityInfo/GetProcessTimes官方文档（2026-11-15已核），均使用handle，不把SACL纳入权限修改。

本轮验证：ilucas实际Windows原生构建；系统Node25与包内Node24.19.0加载同一N-API8产物。Node24五项独立ACL/.NET birth/Unicode目录继承测试通过；macOS相关CLI71/71、Desktop Main101/101、TypeScript检查通过。第二轮独立审查正在复核，不将未验Electron/CI记为通过。

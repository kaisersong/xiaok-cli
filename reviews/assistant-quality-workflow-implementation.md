# Workflow adversarial design (before production)
Freeze population/protocol/sample/binding before predictions. Main-only batch port owns shared 6/48k/6k budget. Prediction defaults unknown, one write before export, expected digest required. Export locks predictions. Native save confirms minimal source-fact export; main must redact credentials from bounded title/summary before supplying population. Import allows only exact case IDs + human labels, never protocol/predictions/pass flags. Native confirmation attests human provenance; metrics cannot prove provenance.

Attack checks: nonuser calls, oversized files, forged pass flags, missing/duplicate/substituted cases, post-export prediction edits, binding/scopes/contract drift, revoke/replay, persisted corruption and reopen. SQLite helpers use LoopStore connection with nested SAVEPOINT; root reads actual DB profile/context/assessment at delivery. Main synchronizes context on grant/contract changes before delivery. Pending work must bind assessmentId/generation/digest. Kimi review coordinated by main owner, pending. Synthetic tests are never real pilot evidence.

## Main wiring API

`new AssistantQualityWorkflow(db: DatabaseSync, ports: AssistantQualityPorts)` uses LoopStore's existing connection. `migrateAssistantQuality(db): void` creates feature tables. `syncAssistantQualityContext(db, context: QualityContext | null): void` is main-only and must be invoked on contract/source-grant changes; null invalidates. Context = binding + scopes + analysisContract + modelEpoch + configFingerprint. Fingerprint/epoch must cover actual provider/model/config/key grant, and `ports.readCurrentModel()` must reread actual trusted configuration, not the context table or startup cache. No config path is accepted by this service.

`population(): Promise<AssistantQualityPopulation>` supplies complete IDs, frozen binding/protocol, bounded credential-redacted sample facts (id/title/status/updatedAt/optional promptSummary/optional severe). `severe` is determined by main from predeclared risk rules/structured facts or prior human risk annotation; null/missing blocks qualification. Model output cannot include severe. Export discloses this risk policy. No raw body/log/credentials are accepted as fields.

`predict(frozenDatasetWithFacts, expectedDigest): Promise<Array<{id,prediction}>>` is optional, main-private and responsible for real shared-ledger metering. Dataset/facts passed to this callback are copies; response must cover exact sample IDs once. Without prediction port outputs remain unknown. `save(contents): Promise<boolean>` owns native save picker and explicit minimal-source consent; `open(maxBytes): Promise<string|null>` owns native open picker, must enforce bytes before reading; `confirmHumanReview(): Promise<false|{userId,text}>` obtains actual local user identity and native explicit human-review attestation. Renderer cannot supply paths/body/pass flags/identity.

Service semantic requests: freeze({requestSource}), recordPredictions({requestSource,assessmentId,expectedDigest}), export({requestSource,assessmentId}), import({requestSource}), revoke({requestSource}), status({requestSource}), readiness({requestSource}). Mutation/status operations accept only user; main-private readiness accepts explicit user or scheduler and denies agent/missing source. Status exactly follows main DTO fields; main adapts public getQualityStatus/exportQualityReview/importQualityReview/revokeQualityReview and explicit renderer attestHumanReview flag. Export blank package contains frozen + labels; user edits labels only.

Owner final gate calls `readCurrentAssistantQualityAssessment(db, readCurrentModel?, expected?: {assessmentId,generation,digest})`. Missing reader fails closed. Main analysis calls readiness({requestSource:'scheduler'}), whose WeakMap capability checks the pure validator at every use. Pure validator never mints tokens and reads current DB snapshot. Root never accepts renderer token/canNotify. Revocation allows explicit reattestation only of still-current context; source/model changes require new freeze, and old pending generation remains invalid. Durable attestation states user-attested, independentlyVerified=false, actual confirmation text/user/time. Historical evaluation window is not an expiry claim.

Source epoch must equal live `assistant_profiles.updated_at` (positive safe integer), in addition to matching active status and exact current scopes. Pause/regrant with identical scopes cannot reuse an older assessment. Main sourceId is internal_snapshot_v1; main computes accountScopeHash from fixed real dataRoot + profileId + sorted scopes. Model reader is supplied by main's fixed-path `readAssistantModelIdentity()` implementation.

Native `save(contents, assertCurrent): Promise<boolean>` must invoke assertCurrent after the picker/consent and immediately before file write. Import captures generation before awaiting native attestation and rejects any intervening revoke. Thus an in-flight older confirmation cannot silently bind itself to a newer generation. Actual raw review bytes, frozen predictions, report digest and native attestation are persisted together. No new background process owner is introduced.

## Usable pre-prediction human risk review

Unknown severe labels are handled by a first human stage, rather than permanent blocking. Export selects type=risk_review for incomplete risk coverage, with frozen binding/protocol/facts and riskLabels[{id,severe:null}]; there are no model predictions in that package. Native-attested import requires exact sample IDs, boolean severe labels, original digest and unchanged frozen metadata. Existing known severe facts cannot be downgraded. Risk import atomically persists original risk review bytes and separate risk attestation, fills facts.severe and dataset.severe, updates digest, and returns phase=frozen. It does not issue qualification. Only one risk import is accepted, before any model prediction. Missing sample facts are rejected during freeze.

Main calls currentReview({requestSource:'user'}) to obtain {assessmentId,digest,generation,phase,riskCoverageComplete}. After risk import it must obtain the new digest, call recordPredictions with that digest, then export again. The second package uses type=action_review and has only action labels editable; severity edits or a later risk_review import are rejected. confirmHumanReview(kind:'risk_review'|'action_review') receives the stage so native confirmation can use the right attestation text. Existing known main risk facts can skip the initial human risk stage. The default undefined main severity is now a usable risk-review path.

Tests were updated first: before production risk support, the new risk flow incorrectly allowed recordPredictions with unknown risks and failed its expected rejection; the new action discriminator was also rejected by old schema. After implementation the complete two-stage production-entry test and risk duplicate/missing/null/replay negatives pass. Fixture risk/action labels are synthetic testing data only.

# Real quality review workflow and revocable notification qualification

The existing in-memory qualification factory is not a usable product workflow: main never imports real labels and the independent notification owner cannot validate current qualification. This change adds a fixed local workflow without manufacturing human labels or turning tests into pilot evidence.

Main freezes the actual current profile/source binding, analysis contract, evaluation window, population IDs and deterministic sample before predictions/labels are imported. A native save dialog exports the review package; a native open dialog imports a bounded strict review file. Renderer/model never selects a filesystem path, supplies qualification flags or issues a token. Human provenance is explicitly attested by the user at import; metrics cannot prove a person actually labeled the data. Missing labels remain unknown and cannot grant qualification. Real case IDs must match the main-frozen population/sample exactly; protocol/risk rules/sample seed/contract cannot be changed at import to fit predictions.

LoopStore owns population/review/qualification records in its current SQLite transaction. The accepted assessment is persisted as original review + report digest + original binding; on startup main revalidates it against current scopes and model contract before issuing the ephemeral WeakMap capability. Disable/revoke has a durable monotonic generation. No in-memory token is serialized as authority.

The notification owner independently reads the fixed Loop database, validates the persisted assessment and current profile/scope/model binding, then computes qualificationCurrent. Pending delivery must be bound to the exact assessment/revision. No callback supplied by RPC, no renderer canNotify. Absence/corruption/mismatch/revocation suppresses. A model contract change requires new evaluation; profile/source revocation must invalidate the binding before subsequent notification can pass.

Tests must exercise production export/import and SQLite reopen, edits to population/protocol/predictions, fabricated pass flags, nonuser calls, invalidation at the final OS gate. Real qualification remains absent until actual labels are supplied. Existing direct-launch pilot gating is unchanged until actual 10-case comparisons and 20 handoffs, not component fixtures.

Adversarial self-review: imported files are untrusted bounded data, not paths/commands; saved files contain only explicitly consented source facts needed for human review and never credentials; source-bound identifiers stay scoped; account/model/scope mismatch cannot reuse a passing result; cleanup owns only this feature's records. An exported blank review is not a successful assessment. User participation in real labeling is intrinsically external and must be reported honestly.

## Independent design review adjudication

There is one durable authority: the accepted assessment and monotonic generation in LoopStore. The WeakMap token is a derived main-only capability used only by analysis readiness and per-await publication guards, never a notification authorization. Every use reloads current assessment generation, profile/source binding and current model contract; no startup-only cache can authorize later analysis. The independent notification owner computes qualificationCurrent itself from the durable current record at the final gate. Renderer/UI cannot pass a token or canNotify. The review suggestion to forbid a capability from every analysis gate would remove the existing fail-closed analysis contract, so its intended single-authority requirement is implemented by deriving and revalidating, rather than deleting that gate.

Main recomputes metrics with its own frozen predictions and imported human labels; predictions/metrics supplied in the imported file must match or be rejected. Report digest covers the original frozen predictions. Attestation text/time/user identity are durable; reports identify human provenance as user-attested and not independently verified. Source/model epochs and assessment generation are covered by the binding. Revision changes suppress old pending envelopes rather than silently rebinding. A user may reimport the same still-current review after an explicit user revocation, with a new explicit human-review attestation and generation; source/model revocation requires a new matching frozen evaluation. The historical evaluation window is not a token-expiry claim.

Export UI states the exact minimal fields (case ID/title/status/time/necessary bounded context) and no credentials, contacts, participants or calendar body by default. Read-only owner connections use current SQLite snapshots, never a cached qualification. Two imports serialize under the existing LoopStore transaction. No old renderer canNotify API exists in the assistant typed IPC allowlist; negative tests forbid paths/qualified/actor fields and require explicit human attestation.
